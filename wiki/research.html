מחקר CSG

ממשק manifold-3d v3.4 - מלכודות ב-WASM

ספריית manifold-3d מבטיחה פלט watertight אבל יש לה דרישות API ספציפיות שנתגלו בפיתוח:

שמות מתודות WASM

ה-API בזמן ריצה משתמש בשמות עם קו תחתון, שונים מהגדרות ה-TypeScript:

// TypeScript declarations say:
manifold.splitByPlane(normal, offset)

// Actual WASM runtime methods:
manifold._SplitByPlane({x, y, z}, offset)  // takes {x,y,z} object, not array
manifold._TrimByPlane({x, y, z}, offset)   // trims one side
manifold._GetMeshJS()                       // extracts mesh data
manifold.add(other)                         // boolean union
manifold.subtract(other)                    // boolean subtract

בניית MeshGL

// What works:
new wasm.Manifold({
  numProp: 3,
  vertProperties: Float32Array,
  triVerts: Uint32Array
})

// Status checking:
manifold.status()  // returns "NoError" (string), not 0 (number)

ממצאים מרכזיים

  • setup() מחזיר אובייקט ריק - אין Mesh class זמין
  • קובץ WASM חייב להיות מוגש עם MIME type נכון - הועתק ל-public/manifold.wasm
  • צריך locateFile callback למצב Vite dev
  • _GetMeshJS() מחזיר vertProperties עם numProp שיכול להיות > 3
בעיית ה-Non-Manifold

האתגר הבסיסי: manifold-3d דורש קלט watertight, אבל רוב ה-meshים לא כאלה.

מקורות גאומטריה לא-manifold

מקורבעיהניתן לתיקון?
Three.js ExtrudeGeometryקודקודים כפולים (normals per-face)כן - mergeVertices()
STL מיובאחורים, חיתוכים עצמייםחלקית
OBJ מיובאקצוות פתוחים, T-junctionsחלקית
Mesh מותאםתלוי בבנייהכן אם בונים נכון

אפשרויות תיקון שנחקרו

  • MeshLib (meshlib.io) - C++ עם תמיכת WASM. Pipeline תיקון מלא. אין npm package - צריך לבנות ממקור.
  • meshoptimizer - אופטימיזציה בלבד, לא תיקון.
  • opencascade.js - תיקון BREP, לא ברמת mesh. יותר מ-20MB WASM.
  • Admesh - משמש את PrusaSlicer. ממלא חורים קטנים, מתקן normals. לא זמין כ-JS.

הפתרון שלנו: CSG דו-שכבתי

Tier 1: manifold-3d
  - לגאומטריה תוכניתית (rails, primitives)
  - מובטח manifold אם בנוי נכון
  - משתמש ב-mergeVertices() + validation

Tier 2: three-bvh-csg (fallback)
  - למודלים מיובאים (STL/OBJ)
  - מקבל כל גאומטריה
  - פלט לא מובטח watertight
  - מציג אזהרה למשתמש
תובנה מפתח

עבור גאומטריה תוכניתית, כשל manifold הוא באג ב-generator שלנו, לא בעיית תיקון. הקריאה ל-merge() מטפלת בחוסר ההתאמה בין פורמט הרנדור של Three.js לטופולוגיה manifold.

מחקר רנדור

Matcap מול PBR מול תאורת סביבה

הבעיה

ב-Electron, פריסטים של HDRI Environment מ-drei לא נטענים באופן אמין. חומרי PBR ללא environment maps נראים שטוחים. ContactShadows גורם לריצוד.

גישות שנוסו

גישהתוצאה
Environment preset="studio"עובד בדפדפן, לא תמיד ב-Electron
Programmatic PMREMGeneratorריצוד - נבנה מחדש כל פריים
ContactShadowsריצוד - רנדור offscreen כל פריים
MeshStandardMaterial + אורותשטוח ללא environment
MeshMatcapMaterial (נבחר)מושלם: ללא אורות, ללא HDRI, ללא ריצוד

מימוש Matcap

  • טקסטורת canvas פרוצדורלית 512x512
  • תאורת סטודיו מובנית: key light, fill, rim, specular, Fresnel
  • שני matcaps: חימר (ברירת מחדל) ונבחר (כחול)
  • נבנים פעם אחת ברמת מודול, cached לתמיד
  • toneMapped={false} על קווי wireframe

מניעת ריצוד

Root cause: continuous rendering (60fps) when nothing changes.

Solution: frameloop="demand"
  - Canvas renders ONLY when invalidate() is called
  - OrbitControls: onChange → invalidate()
  - Store changes: useEffect → invalidate()
  - GizmoHelper: onUpdate → invalidate()
  - StaticGrid: useMemo, never re-renders

בניית מסגרות

גישת Beam + Miter Cut

הבעיה עם Spline Extrusion למצולעים

הוצאת פרופיל לאורך path מצולע יוצרת פינות מעוגלות כי כיוון ה-"החוצה" משתנה בפתאומיות בקודקודים. computeVertexNormals ממצע normals ומחליק את הפינות.

הפתרון: בניית מסגרות כמו בעולם האמיתי

1. יצירת קורה ישרה עם חתך פרופיל
2. חיתוך שני הקצוות בזווית ה-miter
3. הנחת קורות על צלעות המצולע
4. הקורות נפגשות בדיוק בפינות

Miter angle = exteriorAngle / 2
  Rectangle: exterior = 90°  → miter = 45°  → tan = 1.0
  Hexagon:   exterior = 60°  → miter = 30°  → tan = 0.577
  Triangle:  exterior = 120° → miter = 60°  → tan = 1.73
סדר Winding

Path של מלבן ושל מצולע חייבים להשתמש באותו winding (CCW). סדר שונה גורם לכיוון ה-"החוצה" להתהפך ושובר את חיתוכי ה-miter.

SplineExtruder למסגרות מעוקלות

אלגוריתם

1. דגימת ה-path curve ב-N נקודות מרווחות שווה
2. בכל נקודה: חישוב מיקום, tangent, normal חוצה
3. הנחת חתך פרופיל בכל נקודת דגימה (טבעת קודקודים)
4. חיבור טבעות סמוכות עם משולשים
5. סגירת הלולאה (טבעת אחרונה מתחברת לראשונה)

Outward = ניצב ל-tangent במישור XY
  outward = (-tangent.y, tangent.x, 0)
  וידוא שה-outward מצביע הרחק ממרכז ה-path

הערות Three.js

מלכודות שנתגלו
  • ExtrudeGeometry תמיד מוציא לאורך ציר Z. צריך לסובב אחרי יצירה עבור כיוונים אחרים.
  • computeVertexNormals() ממצע normals על קודקודים משותפים ב-index buffer. לקצוות חדים, צריך קודקודים נפרדים (toNonIndexed()).
  • mergeVertices(geo, tolerance) ממזג לפי כל ה-attributes, לא רק position. מתאים להמרת manifold.
  • BufferGeometry.applyMatrix4() משנה קודקודים במקום. בלתי הפיך.
  • MeshMatcapMaterial עם scale שלילי יוצר שיידינג הפוך. משתמשים ב-DoubleSide וקבוצות עוטפות למראות.
  • TransformControls חייב להתחבר לאובייקט בתוך ה-scene graph. רפרנסים ל-Object3D עצמאיים לא עובדים.
  • WireframeGeometry חייב להיווצר מחדש כשהגאומטריה המקורית משתנה (שימוש ב-useMemo).
שיקולי ביצועים
  • frameloop="demand" - האופטימיזציה החשובה ביותר. מוריד שימוש GPU מ-100% לכמעט 0% במצב מנוחה.
  • Matcap textures - נבנים פעם אחת ברמת מודול. לעולם לא נבנים מחדש.
  • useMemo לחומרים - מונע יצירה מחדש של material בכל render.
  • Cloner instances - כל clone הוא mesh נפרד. ל-60+ clones, צריך לעבור ל-InstancedMesh.
  • StaticGrid - LineSegments עם useMemo, ללא shader (Grid של drei גרם לריצוד).
