Research & Technical Notes

CSG (Constructive Solid Geometry)

manifold-3d v3.4 - WASM API Quirks

The manifold-3d library guarantees watertight output but has specific API requirements discovered during development:

WASM Method Names

The runtime API uses underscore-prefixed method names different from TypeScript declarations:

// TypeScript declarations say:
manifold.splitByPlane(normal, offset)

// Actual WASM runtime methods:
manifold._SplitByPlane({x, y, z}, offset)  // takes {x,y,z} object, not array
manifold._TrimByPlane({x, y, z}, offset)   // trims one side
manifold._GetMeshJS()                       // extracts mesh data
manifold.add(other)                         // boolean union
manifold.subtract(other)                    // boolean subtract

MeshGL Construction

// What works:
new wasm.Manifold({
  numProp: 3,
  vertProperties: Float32Array,
  triVerts: Uint32Array
})

// Status checking:
manifold.status()  // returns "NoError" (string), not 0 (number)

Key Findings

  • setup() returns empty object - no Mesh class available
  • WASM file must be served with correct MIME type - copied to public/manifold.wasm
  • locateFile callback needed for Vite dev mode
  • _GetMeshJS() returns vertProperties with numProp possibly > 3
Non-Manifold Mesh Problem

The fundamental challenge: manifold-3d requires watertight input, but most meshes are not watertight.

Sources of Non-Manifold Geometry

SourceIssueFixable?
Three.js ExtrudeGeometryDuplicate vertices (per-face normals)Yes - mergeVertices()
Imported STLHoles, self-intersections, non-orientablePartially
Imported OBJOpen edges, T-junctionsPartially
Custom vertex meshDepends on constructionYes if careful

Repair Options Researched

  • MeshLib (meshlib.io) - C++ with WASM support. Full repair pipeline. No npm package - must build from source.
  • meshoptimizer - Optimization only, not repair.
  • opencascade.js - BREP healing, not mesh level. 20MB+ WASM.
  • Admesh - Used by PrusaSlicer. Fill small holes, fix normals. Not available as JS.

Our Solution: Two-Tier CSG

Tier 1: manifold-3d
  - For programmatic geometry (frame rails, primitives)
  - Guaranteed manifold if built correctly
  - Use mergeVertices() + validate

Tier 2: three-bvh-csg (fallback)
  - For imported models (STL/OBJ)
  - Accepts any geometry
  - Output not guaranteed watertight
  - Show warning to user
Key Insight

For programmatic geometry, a manifold failure is a bug in our generator, not a repair problem. The merge() call handles the vertex-duplication mismatch between Three.js rendering format and manifold topology.

Rendering

Matcap vs PBR vs Environment Lighting

Problem

In Electron, HDRI Environment presets from drei don't load reliably. PBR materials without environment maps look flat. ContactShadows cause flickering.

Solutions Tried

ApproachResult
Environment preset="studio"Works in browser, not always in Electron
Programmatic PMREMGeneratorFlickering - rebuilds every frame
ContactShadowsFlickering - renders offscreen every frame
MeshStandardMaterial + directional lightsFlat without environment
MeshMatcapMaterial (chosen)Perfect: no lights needed, no HDRI, no flicker

Matcap Implementation

  • Procedurally generated 512x512 canvas texture
  • Studio lighting baked in: key light, fill, rim, specular, Fresnel
  • Two matcaps: clay (default) and selected (blue)
  • Built once at module level, cached forever
  • toneMapped={false} on wireframe lines

Flicker Prevention

Root cause: continuous rendering (60fps) when nothing changes.

Solution: frameloop="demand"
  - Canvas renders ONLY when invalidate() is called
  - OrbitControls: onChange → invalidate()
  - Store changes: useEffect → invalidate()
  - GizmoHelper: onUpdate → invalidate()
  - StaticGrid: useMemo, never re-renders

Frame Construction

Beam + Miter Cut Approach

The Problem with Spline Extrusion for Polygons

Extruding a profile along a polygon path creates rounded corners because the "outward" direction changes abruptly at vertices. computeVertexNormals averages normals, smoothing the corners.

The Solution: Real-World Frame Construction

1. Create a straight beam with profile cross-section
2. Cut both ends at the miter angle
3. Place beams at polygon edges
4. Beams meet precisely at corners

Miter angle = exteriorAngle / 2
  Rectangle: exterior = 90°  → miter = 45°  → tan = 1.0
  Hexagon:   exterior = 60°  → miter = 30°  → tan = 0.577
  Triangle:  exterior = 120° → miter = 60°  → tan = 1.73

Miter Cut Implementation

For each vertex in the profile ring at beam end:
  widthOffset = (u - 0.5) * frameWidth
  miterShift = widthOffset * tan(miterAngle) * sign
  // sign = +1 at start, -1 at end

vertex.x = base.x + outward.x * widthOffset + beamDir.x * (miterShift + overlap)
vertex.y = base.y + outward.y * widthOffset + beamDir.y * (miterShift + overlap)

// overlap = 0.1mm to prevent Z-fighting gaps at joints
// No cap faces needed - beams overlap at joints
Winding Order

Rectangle path and polygon path must use the same winding (CCW). Different winding causes outward direction to flip, breaking miter cuts.

SplineExtruder for Curved Frames

Algorithm

1. Sample path curve at N evenly-spaced points
2. At each sample: compute position, tangent, outward normal
3. Place profile cross-section at each sample (ring of vertices)
4. Connect adjacent rings with triangle faces
5. Close the loop (last ring connects to first)

Outward = perpendicular to tangent in XY plane
  outward = (-tangent.y, tangent.x, 0)
  Ensure outward points away from path center

CatmullRom vs LineCurve

  • Smooth paths (circle, ellipse, freehand): CatmullRomCurve3 with tension 0.5
  • Sharp paths (polygon): Direct vertex placement per edge, no curve interpolation

Three.js Technical Notes

Key Gotchas
  • ExtrudeGeometry always extrudes along Z axis. Must rotate after creation for other orientations.
  • computeVertexNormals() averages normals across shared vertices in index buffer. For sharp edges, need separate vertices (use toNonIndexed()).
  • mergeVertices(geo, tolerance) from BufferGeometryUtils merges by ALL attributes, not just position. This is fine for manifold conversion.
  • BufferGeometry.applyMatrix4() transforms vertices in place. Irreversible.
  • MeshMatcapMaterial with negative scale creates inverted shading. Use DoubleSide and wrapper groups for mirrors.
  • TransformControls must attach to an object IN the scene graph. Standalone Object3D refs don't work.
  • WireframeGeometry must be recreated when source geometry changes (use useMemo).
Performance Considerations
  • frameloop="demand" - most important optimization. Reduces GPU usage from 100% to near 0% when idle.
  • Matcap textures - built once at module level (const CLAY_MATCAP = buildMatcap()). Never rebuilt.
  • useMemo for materials - prevents material recreation on every render.
  • Cloner instances - each clone is a separate <mesh>. For 60+ clones, should switch to InstancedMesh.
  • StaticGrid - LineSegments with useMemo, no shader (drei Grid caused flickering).
